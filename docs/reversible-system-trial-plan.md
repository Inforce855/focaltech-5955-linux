**Status 17 October 2026: staging, normal-system activation/discovery, and explicit rollback all PASSED. The temporary system trial was removed.** The current independent GitHub build and private D-Bus physical Discover/Claim/Release both **PASSED**; the next meaningful difference to test is whether the standard Nobara **system** `fprintd` instance can enumerate/open the reader with our exact custom libfprint, without touching authentication.

## Implemented staging and activation procedure (17 October 2026)

The read-only Nobara preflight reported **Nobara 44**, `fprintd 1.94.5-5.fc44`, `libfprint 1.94.100-1.fc44`, `fprintd-pam` absent, a **currently inactive** `fprintd.service`, no existing `/etc/systemd/system/fprintd.service.d/` override, with `ProtectHome=yes`, `ProtectSystem=strict`, `PrivateTmp=yes`, `NoNewPrivileges=yes` and `DeviceAllow=char-usb_device rw`. The only existing global service drop-in was `/usr/lib/systemd/system/service.d/10-timeout-abort.conf`. This state was checked **before any write**; the activation script deliberately rechecks it immediately before installing.

The reviewed-scope procedure has two **distinct** actions:

1. **Build/stage as ordinary user, without privilege or USB access:** from the existing separate GitHub checkout, run `python3 tools/verify_ft5955_clean_clone.py --stage`. This independently clones the exact upstream tag, verifies three source patches and existing source manifest, completes Meson/Ninja build, and places a single verified library and hash in `~/.local/state/ft5955-system-trial/stage/` (mode `0700` directory, library and checksum `0600`). It refuses to overwrite an existing staging directory. It does **not** touch `/opt`, `/etc`, installed service, USB or PAM.
2. **Privileged activation only after successful staging and script review:** `sudo bash tools/manage_ft5955_system_trial.sh --activate`. The script refuses a root login shell and unrecognised service versions, existing local overrides, active normal daemon, invalid staging owner/mode/checksum or unexpected unit security properties. It stages the shared library to **root-owned** `/opt/ft5955-system-trial/lib/` and adds only `/etc/systemd/system/fprintd.service.d/90-ft5955-system-trial.conf`, containing `LD_LIBRARY_PATH` to this isolated directory plus `FT5955_EXPERIMENTAL_ENABLE=0` and `UnsetEnvironment=FT5955_ENGINE_GATEWAY`. It reloads systemd, starts the normal `fprintd`, confirms the **exact** newly installed library in `/proc/PID/maps`, and checks only `GetDevices` via system D-Bus. It does **not** request Claim/EnrollStart/VerifyStart, does not add a udev rule and does not touch normal fingerprint storage or passwords. A failure triggers automatic best-effort rollback; always inspect its final output.
3. **Explicit rollback (available even after reboot):** `sudo bash tools/manage_ft5955_system_trial.sh --rollback`. Requires the previously created trial marker, exact drop-in content and installed-library checksum; stops only system `fprintd`, removes only the trial-owned drop-in and separate `/opt` library, reloads systemd and leaves the original RPM-owned binary intact. Returns the fprintd service to on-demand activation with packaged libfprint; keeps the password path unchanged. If trial files have been modified by someone else, fail closed instead of deleting arbitrary content.

**Verified:** both `--stage` and the root installer have now been exercised successfully on the user's Nobara 44 machine, including explicit rollback. See [the dated complete trial record](system-fprintd-install-rollback-pass-2026-10-17.md). The already demonstrated independent clean clone compilation/Claim-only test remains unchanged. Installation is an **opt-in normal-system discovery trial**, not proof of a production-safe biometric matcher, and the previously demonstrated private enrol/verify tests do not automatically carry over to the hardened normal system service. No PAM/login edits are requested.

## Strict trial boundaries

1. Run [read-only preflight](../tools/preflight_ft5955_system_trial.sh) as the normal user and inspect its output **before modifying any system file or starting/stopping any system service**. It reports the current RPM versions, fprintd systemd unit and drop-ins, library locations, service sandbox settings, and clean-builder checkout availability; never prints fingerprint data or modifies anything.
2. Do **not** overwrite an RPM-owned shared library in `/usr/lib64`, `/usr/libexec/fprintd`, unit file in `/usr/lib/systemd/system`, nor any PAM files. Do not `dnf remove` core fingerprint packages or edit `/etc/pam.d/*`, `authselect`, KDE display-manager login configuration, `/var/lib/fprint`, or enroll/delete fingerprints.
3. Proposed install mechanism *after preflight*: place a reviewed, hash-checked trial `libfprint-2.so.2*` separately under a dedicated root-owned location, preserving symlink/SONAME relationships and provenance; use a minimal, *clearly owned* reversible `fprintd.service` override (e.g. scoped `LD_LIBRARY_PATH`) **only if the actual systemd unit/activation/SELinux policy is compatible**. Do not apply this blindly. Record any previous override and actual system service state before activation. Test loading the exact shared object using `/proc/PID/maps`, not merely enumeration. Be able to restore the prior service configuration and stop the trial on failure. Package updates must not overwrite the test files.
4. **Never enable experimental fingerprint matching for this initial system-level trial.** Explicitly leave `FT5955_EXPERIMENTAL_ENABLE` unset or set to `0`; do not supply `FT5955_ENGINE_GATEWAY` to the production system service. The current experimental MOH matching bridge has only been validated in a **non-root private environment**; fprintd's normal unit runs as a system service with extra sandbox restrictions. An apparent KDE device entry cannot be equated with working enrollment/verification. GUI enroll buttons must not be used in this phase.
5. The only initially permitted action is requesting normal system `fprintd` **device discovery and, if safe, an explicit device Claim/Release** through a narrow client. No `fprintd-enroll`, `fprintd-verify` or authentication changes. Avoid repeated real fingerprint touches.
6. Before any subsequent experimental enrolment, have a separately reviewed non-root matching isolation design, persistent-template confidentiality review, offline matcher cancellation/error mapping audit and an explicit decision about whether a normal system service can safely launch the proprietary engine. **Completely native matching remains the longer-term goal, not accomplished by replacing libfprint alone.**
7. **Rollback requirement:** the implementation must provide an explicit, idempotent rollback command that restores the original unit configuration and runtime library mapping without reinstalling software. Verify `fprintd` after rollback once, and verify no accidental drop-in remains. Keep a functioning **password login** available throughout. If existing fingerprint/PAM auth is already configured for another sensor, assess the impact first.

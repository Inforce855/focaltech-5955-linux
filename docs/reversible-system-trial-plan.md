# FocalTech 5955 — reversible Nobara system-service trial (planned)

**Status 17 October 2026: preparing the trial. No system installation has occurred.** The current independent GitHub build and private D-Bus physical Discover/Claim/Release both **PASSED**; the next meaningful difference to test is whether the standard Nobara **system** `fprintd` instance can enumerate/open the reader with our exact custom libfprint, without touching authentication.

## Strict trial boundaries

1. Run [read-only preflight](../tools/preflight_ft5955_system_trial.sh) as the normal user and inspect its output **before modifying any system file or starting/stopping any system service**. It reports the current RPM versions, fprintd systemd unit and drop-ins, library locations, service sandbox settings, and clean-builder checkout availability; never prints fingerprint data or modifies anything.
2. Do **not** overwrite an RPM-owned shared library in `/usr/lib64`, `/usr/libexec/fprintd`, unit file in `/usr/lib/systemd/system`, nor any PAM files. Do not `dnf remove` core fingerprint packages or edit `/etc/pam.d/*`, `authselect`, KDE display-manager login configuration, `/var/lib/fprint`, or enroll/delete fingerprints.
3. Proposed install mechanism *after preflight*: place a reviewed, hash-checked trial `libfprint-2.so.2*` separately under a dedicated root-owned location, preserving symlink/SONAME relationships and provenance; use a minimal, *clearly owned* reversible `fprintd.service` override (e.g. scoped `LD_LIBRARY_PATH`) **only if the actual systemd unit/activation/SELinux policy is compatible**. Do not apply this blindly. Record any previous override and actual system service state before activation. Test loading the exact shared object using `/proc/PID/maps`, not merely enumeration. Be able to restore the prior service configuration and stop the trial on failure. Package updates must not overwrite the test files.
4. **Never enable experimental fingerprint matching for this initial system-level trial.** Explicitly leave `FT5955_EXPERIMENTAL_ENABLE` unset or set to `0`; do not supply `FT5955_ENGINE_GATEWAY` to the production system service. The current experimental MOH matching bridge has only been validated in a **non-root private environment**; fprintd's normal unit runs as a system service with extra sandbox restrictions. An apparent KDE device entry cannot be equated with working enrollment/verification. GUI enroll buttons must not be used in this phase.
5. The only initially permitted action is requesting normal system `fprintd` **device discovery and, if safe, an explicit device Claim/Release** through a narrow client. No `fprintd-enroll`, `fprintd-verify` or authentication changes. Avoid repeated real fingerprint touches.
6. Before any subsequent experimental enrolment, have a separately reviewed non-root matching isolation design, persistent-template confidentiality review, offline matcher cancellation/error mapping audit and an explicit decision about whether a normal system service can safely launch the proprietary engine. **Completely native matching remains the longer-term goal, not accomplished by replacing libfprint alone.**
7. **Rollback requirement:** the implementation must provide an explicit, idempotent rollback command that restores the original unit configuration and runtime library mapping without reinstalling software. Verify `fprintd` after rollback once, and verify no accidental drop-in remains. Keep a functioning **password login** available throughout. If existing fingerprint/PAM auth is already configured for another sensor, assess the impact first.

## What we know now

- Clean independent source from official libfprint `v1.94.100` and reviewed GitHub patches compiled on Nobara, Ninja `109/109`, and private `fprintd` loaded the exact binary and completed real USB discovery/Claim/Release.
- First private Claim was blocked by a Linux USB node ACL, then succeeded after a narrow manual ACL. The manual ACL is distinct from normal system-service permissions and is **not removed** by the test cleanup.
- Official Fedora `fprintd` packaging includes `/usr/lib/systemd/system/fprintd.service` and `/usr/libexec/fprintd`; the service's access control and sandbox configuration must be read from **this exact machine**, not assumed from generic examples.
- The private matching/re-enrolment tests and known genuine false rejects are preserved in [project status](status-2026-10-16.md). Prior cancellation and quality rejection checks need not be repeated just to integrate the system service. Physical unplug of an integrated power-button sensor is neither feasible nor required.

**Action for the user now:** perform the non-root, read-only preflight and provide its concise output. Then the actual trial launcher/rollback will be written to the confirmed Nobara service layout. No unreviewed `sudo` commands.
